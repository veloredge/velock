# Contributing to VeLock

Thanks for taking the time to help. This project is intentionally small, and the
bar for changes is high: the app draws over other apps and freezes input, so a
careless change can leave someone's phone unusable.

## Building and running

```bash
./gradlew :app:assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Requirements: JDK 17 or newer and an Android SDK with platform 34. `local.properties`
is generated by Android Studio and is not committed.

There is no test suite yet. Every change must be verified by hand on a device:

1. Enable the tile, float the padlock, freeze the screen.
2. Confirm the frozen app does not respond to taps.
3. Tap the frozen screen, confirm the padlock wakes, then unlock.
4. Drag the padlock to the bin and confirm the overlay and the service both stop.
5. `adb shell dumpsys window windows | grep VeLock` must return nothing after
   removing the lock. Leftover windows are a bug.

## Ground rules

- **Framework APIs only.** No new dependencies, no AndroidX, no third-party
  libraries. The APK is deliberately tiny and dependency free.
- **Battery first.** No wake locks, no polling, no repeating timers, no sensor
  listeners, no work that runs while the app is idle. A change that keeps the CPU
  awake will be rejected.
- **No accessibility service, no device administrator, no root.** Those are the
  easy way to "really" block a phone and the wrong way for this project.
- **No new permissions** without a clear argument in the pull request. The app has
  no `INTERNET` permission and should keep it that way.
- **Respect the user's escape hatches.** The Quick Settings tile and the
  notification must always be able to stop the lock.
- No emoji in code, names, commits or UI. Icons are vectors.

## Style

- Java, four-space indent, 100 column soft limit.
- Names say what they do. Comments explain why, not what.
- Keep the diff focused; unrelated refactors belong in their own pull request.
- Conventional Commits for messages: `feat:`, `fix:`, `refactor:`, `docs:`,
  `chore:`.

## Reporting bugs

Open an issue with your device model, Android version, and the exact steps that
reproduce the problem. `adb logcat` output helps enormously, but strip anything
personal first.

## Security

Please do not open a public issue for a security problem. See
[SECURITY.md](SECURITY.md).
